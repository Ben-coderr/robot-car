## System Telemetry Overview

The communication stack uses a multi-tier distributed architecture, separating high-bandwidth wireless networking from deterministic real-time hardware execution:

```
┌────────────────────────┐                   ┌────────────────────────┐                   ┌────────────────────────┐
│      Client Device     │                   │       ESP32-CAM        │                   │      Arduino UNO       │
│  (Phone / Tablet / PC) │                   │  (Network & Telemetry) │                   │ (Real-Time Controller) │
└───────────┬────────────┘                   └───────────┬────────────┘                   └───────────┬────────────┘
            │                                            │                                            │
            │ ─── 1. WebSocket ws://192.168.4.1/ws ────► │                                            │
            │      (Command Packets: Drive, Horn, etc)   │ ──── 2. Hardware UART 38400 Baud ────────► │
            │                                            │       (ASCII + XOR Checksum: M,l,r*XX)     │
            │                                            │                                            │
            │                                            │                                     [Motor Drive &]
            │                                            │                                     [Sonar Sensing]
            │                                            │                                            │
            │                                            │ ◄─── 3. Telemetry Feedback ─────────────── │
            │                                            │       (D,angle,cm,flags)                   │
            │ ◄── 4. Broadcast Telemetry & Telemetry ─── │                                            │
            │      (Sync Frame: T,l,r,light,horn,flash)  │                                            │
            │                                            │                                            │
            │ ◄── 5. High-Speed Video Stream ─────────── │                                            │
            │      (MJPEG Port 81: /stream)              │                                            │
```

## 1. Browser ↔ ESP32-CAM (WebSocket Protocol)

Connected clients open a persistent, full-duplex WebSocket connection at `ws://192.168.4.1/ws`. Messages are formatted as lightweight, comma-delimited ASCII strings.

### Client Commands (Browser → ESP32-CAM)

| Command String | Parameters & Range | Transmission Rate | Destination | Description |
|:---|:---|:---:|:---:|:---|
| `M,<left>,<right>` | Left/Right: `-255` to `+255` | Every 100 ms while driving | Forwarded to Arduino | Proportional differential steering speeds |
| `S` | None | On release / Stop tap | Forwarded to Arduino | Immediate emergency stop; sets all PWM to 0 |
| `H,<state>` | `<state>`: `0` (Off) or `1` (On) | On touch down / up | Forwarded to Arduino | Acoustic horn trigger |
| `L,<mode>` | `<mode>`: `0` (Off), `1` (On), `2` (Hazard) | On button toggle | Forwarded to Arduino | Front headlights operating mode |
| `C,<warn>,<stop>,<brk>,<alw>,<mute>` | cm thresholds and boolean flags | Periodic (every 3 sec) | Forwarded to Arduino | Parking radar configuration and alarm parameters |
| `K,<brightness>` | `<brightness>`: `0` to `255` | On slider change | ESP32 Internal | High-power camera flash LED (pin IO4) PWM |
| `F,<framesize>` | Frame size enum (`0` to `10`) | On settings select | ESP32 Internal | Sets camera sensor resolution (QVGA, VGA, SVGA) |
| `Q,<quality>` | JPEG quality: `10` (best) to `63` | On settings select | ESP32 Internal | Sets image compression quality factor |
| `V,<flip>` | `0` or `1` | On toggle | ESP32 Internal | Vertical camera flip |
| `X,<mirror>` | `0` or `1` | On toggle | ESP32 Internal | Horizontal camera mirror |
| `R,<client_type>` | `phone` or `view` | On handshake | ESP32 Internal | Registers client identity for telemetry tracking |

## 2. ESP32-CAM ↔ Arduino UNO (UART Serial Protocol)

Communication between the microcontrollers runs over an asynchronous hardware serial link at **38400 baud, 8 data bits, no parity, 1 stop bit (8-N-1)**:
* **ESP32 IO14 (TX)** → **Arduino D3 (RX)** (3.3V logic level)
* **Arduino D2 (TX)** → **1k/2k Divider** → **ESP32 IO15 (RX)** (5V stepped down to 3.33V)

### Packet Integrity: XOR Checksum Algorithm
To protect motor drive commands from inductive noise generated by TT motor brushes, all commands transmitted to the Arduino terminate with an asterisk `*` followed by a two-character uppercase hexadecimal XOR checksum:

$$\text{Checksum} = \bigoplus_{i=0}^{n-1} \text{ASCII}(\text{payload}[i])$$

**Example Command Packet**: `M,180,-180*`
1. Compute the XOR of every byte before the `*` symbol:
   `'M' ^ ',' ^ '1' ^ '8' ^ '0' ^ ',' ^ '-' ^ '1' ^ '8' ^ '0'`
2. The result evaluates to hexadecimal `0x4D`.
3. The transmitted string is: `M,180,-180*4D\n`.

If the Arduino evaluates a checksum mismatch, the packet is immediately dropped, and the last valid packet persists until the next cycle.

## 3. Real-Time Telemetry Packets (Arduino UNO → ESP32-CAM)

The Arduino continuously samples the ultrasonic rangefinder and broadcasts vehicle telemetry every **60 milliseconds**:

```text
D,<angle>,<distance_cm>,<flags>\n
```

### Parameter Specification
* **`<angle>`**: Scanning sonar angle (default is fixed at `90` degrees straight rear; ranges `30`–`150` if optional SG90 servo is mounted).
* **`<distance_cm>`**: Distance in centimeters (`0` indicating obstacle beyond maximum range > 400 cm).
* **`<flags>`**: 8-bit unsigned integer containing boolean vehicle status flags.

### Telemetry Flag Bitmask Table

| Bit Position | Bitmask Value | Status Flag Name | Meaning When Bit is HIGH (1) |
|:---:|:---:|:---|:---|
| **Bit 0** | `0x01` (`1`) | `FLAG_REVERSING` | Vehicle motors are actively moving in reverse |
| **Bit 1** | `0x02` (`2`) | `FLAG_ALARM_ACTIVE` | Parking proximity alarm is sounding audible alert |
| **Bit 2** | `0x04` (`4`) | `FLAG_AUTOBRAKE` | Auto-brake safety intervention is overriding reverse |
| **Bit 3** | `0x08` (`8`) | `FLAG_HORN` | Acoustic horn is currently sounding |
| **Bit 4** | `0x10` (`16`) | `FLAG_LIGHTS` | Front white headlights are illuminated |
| **Bit 5** | `0x20` (`32`) | `FLAG_HAZARD` | Hazard warning mode is currently flashing |

## 4. Multi-Client Synchronization Broadcasts

To ensure that multiple connected devices (e.g. mobile driver phone and classroom overhead display) stay synchronized in real time, the ESP32 broadcasts two periodic telemetry frames:

### Drive Telemetry Sync Frame (`T` Frame)
* **Broadcast Interval**: Every 250 milliseconds
* **Format**: `T,<left_speed>,<right_speed>,<light_mode>,<horn_state>,<flash_pwm>`
* **Usage**: Keeps UI steering meters, light toggles, and gauge needles synchronized across all browsers.

### System Diagnostics Frame (`I` Frame)
* **Broadcast Interval**: Every 2000 milliseconds (2 seconds)
* **Format**: `I,<wifi_rssi>,<phone_clients>,<uno_status>,<viewer_clients>`
* **Parameters**:
  * `<wifi_rssi>`: Wi-Fi signal strength in dBm (e.g. `-42`).
  * `<phone_clients>`: Count of connected mobile driver devices.
  * `<uno_status>`: `1` if Arduino UART heartbeats are receiving, `0` if link timeout.
  * `<viewer_clients>`: Count of active desktop `/view` observation windows.

## 5. HTTP REST Endpoints

In addition to full-duplex WebSockets, the ESP32-CAM hosts a REST interface for diagnostics, image capture, and external integrations (e.g. MIT App Inventor, Python, or ROS):

| Uniform Resource Identifier | Method | Content Type | Response / Purpose |
|:---|:---:|:---:|:---|
| `http://192.168.4.1/` | `GET` | `text/html` | Main mobile driver application UI |
| `http://192.168.4.1/view` | `GET` | `text/html` | Desktop classroom telemetry viewer |
| `http://192.168.4.1/status` | `GET` | `application/json` | JSON snapshot of distance, battery, and light states |
| `http://192.168.4.1/capture` | `GET` | `image/jpeg` | Captures and downloads single high-resolution still image |
| `http://192.168.4.1:81/stream` | `GET` | `multipart/x-mixed-replace` | Real-time MJPEG live video stream (port 81) |
| `http://192.168.4.1/cmd?c=<command>` | `GET` | `text/plain` | Executes raw string command (e.g. `cmd?c=M,150,150`) |

## 6. Multi-Level Safety & Fail-Safe Watchdogs

To prevent runaway robot conditions caused by Wi-Fi disconnection or software crashes, the system incorporates four independent watchdog timers:

```
[Browser Client]
       │
       │ (Sends M,l,r every 100 ms)
       ▼
[ESP32-CAM Watchdog: 500 ms Timeout] ──(Timeout?)──► Issues Emergency Stop 'S'
       │
       │ (Forwards commands with checksum)
       ▼
[Arduino Uno Watchdog: 600 ms Timeout] ──(Timeout?)──► Cuts All Motor PWM to 0
       │
       ├──► Auto-Brake Logic: If reversing AND distance ≤ Stop Threshold ──► Forces Reverse PWM to 0
       │
       └──► Slew Rate Limiter: Motor PWM increment clamped to 18 units / 10 ms (Prevents VCC sag)
```

1. **Client-Side Touch Watchdog**: When touch contact is lifted from the joystick or the browser tab is hidden/minimized, the client immediately transmits `S` (Emergency Stop).
2. **ESP32-CAM Link Watchdog (500 ms)**: If the ESP32 does not receive a valid drive packet for 500 ms, it assumes network packet loss and transmits `S` over the serial link to the Arduino.
3. **Arduino Motor Watchdog (600 ms)**: If the Arduino does not receive a verified command packet for 600 ms, it automatically drives all motor PWM outputs to zero and silences the buzzer.
4. **Hardware Auto-Brake Override**: When the vehicle is moving in reverse and the rear ultrasonic sonar reports an obstacle within the programmed emergency stop threshold (default: 15 cm), the Arduino firmware unconditionally overrides reverse motor PWM to zero, allowing only forward drive.
5. **Inductive Slew Rate Limiter**: Motor speed transitions are ramped smoothly at a maximum rate of 18 PWM units per 10 ms cycle. This prevents sudden inductive current draws that could pull battery voltage below the dropout threshold of the linear regulators.
